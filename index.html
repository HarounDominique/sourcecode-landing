the problem

AI agents are only as good as the context they receive.

ERR_NO_CONTEXT

Agents start blind

Without repo structure, agents hallucinate imports, file paths, and architecture decisions from the first prompt.

ERR_NOISE_OVERFLOW

Context is noisy

Raw file trees contain benchmark dirs, generated files, tooling configs, and docs that consume tokens without helping.

ERR_ARCH_UNKNOWN

Architecture is invisible

LLMs see files, not systems. They miss layers, plugin systems, entry points, and runtime topology.

ERR_CONTEXT_STALE

Context decays

What you paste today is stale tomorrow. There's no reproducible baseline agents or pipelines can depend on.

ERR_MANUAL_SCALE

Manual context doesn't scale

Handcrafting prompts per project is engineering debt that grows with every new agent, team, and task.

the solution

Structured, reproducible context extracted from your repository.

sourcecode runs a local, static analysis pipeline on your repo and produces a compact structured document ready to inject into any AI coding agent — no LLM calls, no network requests, fully deterministic.

Get started →
  • Stack & framework detection — identifies language, frameworks, and package managers across 10+ languages without config
  • Runtime topology inference — classifies packages as core, plugin, or noise based on how they're actually used
  • Relevance ranking — scores files by git churn × runtime proximity × bootstrap signal, not alphabetical order
  • Noise suppression by default — benchmarks, docs, tooling, and generated files are excluded unless explicitly requested
  • Deterministic outputs — same repo, same version, same output every time. Safe for CI pipelines and caching
  • Confidence-aware — every analysis reports detection quality and lists analysis gaps so agents know what they don't know

quickstart

Up and running in 60 seconds.

Install, run, pipe. No config files. No account required.

01
$ pip install sourcecode
02
# full agent-optimized analysis
$ sourcecode . --agent
 
# task-specific context
$ sourcecode . prepare-context explain
$ sourcecode . prepare-context fix-bug
$ sourcecode . prepare-context onboard
03
# pipe directly into Claude Code
$ sourcecode . --agent | claude -p "Review the architecture"
 
# write to file for session injection
$ sourcecode . --agent --output context.json

output fields

Everything an agent needs to reason over your code.

project_summary

Project summary

One-sentence natural language description of what the project does, its type, and primary stack.

architecture_summary

Architecture

Runtime topology: layers, plugin systems, entry flows, and hub modules that agents need to navigate the codebase.

entry_points

Entry points

Where execution actually starts — production paths only, not benchmarks or docs. Each with kind and confidence.

key_dependencies

Key dependencies

Runtime dependencies with declared version and role classification (runtime / dev / build). Not just a flat list.

relevant_files

Relevant files

Files ranked by usefulness for coding tasks: git churn × runtime proximity × bootstrap signal. Not folder position.

confidence_summary

Confidence summary

Overall detection quality and gap list. Agents know exactly what they don't know — no silent hallucination.

--git-context

Git signals

Recent commits, churn hotspots, and uncommitted changes layered into the context for change-aware tasks.

--code-notes

Code annotations

TODOs, FIXMEs, HACKs, and Architecture Decision Records surfaced as structured context, not buried in comments.

design philosophy

Built on opinions. Held accountable to them.

determinism over approximation

Same repo, same output.

Every run on the same repository produces identical output. Agents, pipelines, and teams can cache it, diff it, and depend on it.

runtime topology over file trees

What runs matters, not what exists.

What matters is where execution starts, what calls what, and which modules are actually critical — not alphabetical file lists.

noise suppression by default

Agents get signal, not inventory.

Benchmark dirs, generated files, tooling configs, and docs are suppressed unless explicitly requested.

local-first, privacy-respecting

No code leaves your machine.

No API keys required. No network requests. Fully offline. Analysis is entirely static and runs on your hardware.

composable, not monolithic

Output is infrastructure.

Pipe it, transform it, inject it, cache it. Structured data that works with jq, claude, cursor, and anything that reads stdin.

confidence-aware

Honest about what it doesn't know.

Every analysis includes a confidence summary and gap list. Agents know what they don't know before they act.

privacy & telemetry

Transparent by default.

Telemetry is opt-in only and disabled by default. Only anonymous usage metadata is ever collected — never code, paths, or content.

data collection policy · v1.0
NEVER Source code contents, file bodies, or repository data
NEVER Credentials, API keys, tokens, or secrets
NEVER Repository names, paths, or directory structures
OPT-IN Anonymous usage metrics (invocation count, flags used, error types)
OPT-IN Aggregated performance telemetry (run duration, output size buckets)

Manage with: sourcecode telemetry status · sourcecode telemetry enable · sourcecode telemetry disable
